# Funding feature and statistical test specification

## Authority and locked economic gate
`research_v2/FUNDING_GATE_v1.md` is authoritative. This document makes the implementation and deterministic statistical calculations explicit; it does not authorize or execute the economic workflow.

Locked criteria:
1. At least 300 resolved OOS trades total from at least 3 assets.
2. Strict net profit > 0 after 0.45% round-trip cost per trade.
3. Funding model must beat both the v4 no-Funding baseline and Buy & Hold. The two one-sided hypotheses are corrected together by Holm; both adjusted p-values must be <= 0.05.
4. Maximum drawdown from the daily equal-weight portfolio equity curve <= 20%.
5. Only the first complete economic run is authoritative. Technical-bug fixes may be separately logged; no later run replaces the first complete result.
6. Any failed condition closes the research project; only the signal-bot forward test through 100 trades remains.

## Funding feature
- Exactly one feature: the latest raw rate from fetched `FundingEvent` history with `event.timestamp_ms <= candle.close_time_ms`.
- An event at the exact close timestamp is included; an event at close + 1 ms is excluded.
- No averaging, rolling window, conversion, normalization, artificial lag, or additional parameter.
- Existing `join_funding_feature` and `project60_rows` are untouched.
- Funding disabled is the default and must match the original release walk-forward function on the same fixed deterministic fixture. The test reference is pinned to release commit `0630706dc655366042c073cebc44aebad070b39e`, not the modified function.
- Funding enabled appends only the seventh raw feature column. The existing six feature columns and labels remain unchanged.

## Portfolio return definitions
- Equal capital weight across assets; no leverage.
- Strategy daily asset return is zero on a day with no trade. For each completed round-trip trade that day, deduct 0.45 percentage points from that asset's daily gross return.
- Daily portfolio return is the arithmetic mean of the assets' daily net returns.
- Buy & Hold uses the same assets, dates, and equal weights, with one 0.45% round-trip cost charged at inception.
- Daily equity compounds as `equity[t] = equity[t-1] * (1 + daily_return_pct[t] / 100)`; drawdown is measured against the running peak.

## Statistical protocol
- Paired observations: daily portfolio net-return series for candidate and each comparator.
- Block Bootstrap: circular moving blocks of 5 consecutive days; 10,000 resamples; deterministic seed `20261109`.
- One-sided alternatives: Funding > v4 baseline; Funding > Buy & Hold.
- For each comparison, use paired daily differences. The null distribution is generated by centering the observed paired differences at zero, resampling contiguous 5-day blocks, and calculating the null mean. The one-sided p-value is `(1 + count(null_mean >= observed_mean)) / (10000 + 1)`.
- Holm correction is applied jointly to exactly two p-values, preserving hypothesis order. The adjusted values are `max(previous_adjusted, min(1, (m-rank) * p_sorted))` mapped back to original order.
- The implementation exposes these deterministic calculations as pure functions. Unit tests use synthetic series only; they do not constitute the economic Gate run.

## Technical tests
- Timestamp boundary: exact close included, +1 ms excluded.
- Model shape: enabled path fits seven-column feature rows.
- Disabled parity: compare output fields with the pinned original-release walk-forward function.
- Portfolio daily net return and strict cost: manually calculable synthetic example.
- Buy & Hold: same weights and one-time strict cost, manually calculable synthetic example.
- Holm: known two-hypothesis examples.
- Bootstrap: identical series must not be significant; clearly superior series must be significant.
- Gate boundary: 299 resolved trades must fail; 300 across 3 assets can pass when other conditions pass.
